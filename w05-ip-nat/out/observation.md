Task 1
    1. _parse_ipv4(address) : IP주소를 입력받음, IP주소의 형태와 범위가 맞는지 확인하고 IP주소를 Int형으로 변환하여 리턴
    
    2._int_to_ipv4(value) : 정수를 IP주소의 형태로 바꿈 

    3. parse_cidr(cidr) : cidr의 형태 (ip주소 / 프리픽스 값)를 확인함. 프리픽스 값에 따라 마스크를 만들고 ip주소에 씌움, 해당 값이 ip주소와 일치하는지 검사 

    자세한 과정 : 192.168.1.25/24 가 cidr로 입력된다면, 앞 24비트를 1로 채운 255.255.255.0의 형태로 네트워크 마스크를 만듦.
    여기서 0은 임의의 수를 뜻함.
    입력받은 cidr과 네트워크 마스크의 and 연산시, 
    192.168.1.0이 나올것임. 192.168.1.25와 다르므로 reject.

    4. network_range(cidr) : cidr를 입력받음. 프리픽스 값으로 호스트의 ip주소 확인 _int_to_ipv4() 메소드로 해당 ip의 범위를 리턴함

    5. add(self, cidr, next_hop) : cidr을 입력받음, 라우팅 테이블에 경로 추가

    6.lookup(self,adress) : ip주소를 입력받아 정수로 바꿈, 모든 라우팅 테이블을 탐색, 루트가 같고 프리픽스가 가장 긴 네트워크를 next_hop으로 저장함.

Task 2 DORA(DHCP가 IP를 할당하는 과정)
    Wireshark를 이용하여 DHCP 패킷을 캡처한 결과, DHCP Discover → Offer → Request → ACK의 DORA 과정을 확인하였다. Discover 패킷의 출발지 주소는 0.0.0.0, 목적지 주소는 255.255.255.255였다. 클라이언트가 아직 IP 주소를 할당받지 않은 상태이므로 출발지 IP로 0.0.0.0을 사용하며, DHCP 서버의 주소를 아직 모르기 때문에 브로드캐스트(같은 네트워크 기기에게 뿌리기)를 사용한다. DHCP 서버는 192.168.0.1이고, 클라이언트에 192.168.0.35 주소를 할당하였다. DHCP ACK에서 확인한 IP 주소의 임대 시간(Lease Time)은 2시간이었다.
    
Task 3
    라우터의 LPM 빠르게 찾기.
    LPM : 목적지 IP가 여러개 있을때 가장 긴 프리픽스 경로 찾기

    Yourtable : 프리픽스 범위 0~32까지의 딕셔너리 만듦, 각 경로를 프리픽스 길이별로 딕셔너리에 저장함. 경로 검색시 32번째 인덱스부터 0까지 역순으로 검사. 딕셔너리에 저장된 목적지 IP에 해당 프리픽스 길이의 네트워크 마스크를 씌우고 일치한다면 다음 목적지로 리턴함.

    정리 : 긴 프리픽스부터 검색하는것이 정확도를 유지하면서도 속도가 더 빠르다
