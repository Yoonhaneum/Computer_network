            Task 1 — Learning Switch 관찰

1. 프레임을 수신한 포트로 다시 전송하지 않는 이유

스위치는 프레임이 들어온 포트를 제외한 포트로 프레임을 전달한다. 프레임을 수신한 포트로 다시 전송하면 해당 "프레임이 불필요하게 되돌아가 네트워크 트래픽이 증가할 수 있기 때문이다." 특히 목적지 MAC 주소를 알 수 없어 프레임을 플러딩하는 경우에도 수신 포트는 제외해야 한다. 따라서 스위치는 프레임을 받은 포트를 제외한 나머지 포트로만 전달한다.

2. 목적지를 모르는 스위치는 플러딩하지만 라우터는 패킷을 버리는 이유

스위치는 목적지 MAC 주소를 학습 테이블에서 찾을 수 없으면 목적지 장치가 연결된 포트를 알 수 없다. 따라서 프레임을 수신한 포트를 제외한 모든 포트로 전달하는 플러딩을 수행한다. 이를 통해 목적지 장치가 연결된 포트에 프레임이 도달할 수 있다.

반면 라우터는 IP 주소와 라우팅 테이블을 이용해 목적지 네트워크로 전달할 경로를 결정한다. 목적지 네트워크에 대한 경로가 없으면 올바른 다음 홉을 결정할 수 없으므로 일반적으로 패킷을 폐기한다. 즉, 스위치는 목적지 MAC 주소를 모를 때 전달 가능성을 확보하기 위해 플러딩하지만, "라우터는 목적지 네트워크로 가는 경로를 찾지 못하면 패킷을 전달하지 않는다."

3. 타임아웃 기반 에이징의 한계와 개선 방법

타임아웃 기반 에이징은 일정 시간 동안 프레임이 관찰되지 않은 MAC 주소 항목을 학습 테이블에서 제거하는 방식이다. 이번 구현에서는 마지막으로 관찰된 시각으로부터 300초 이상 지난 항목을 제거한다.

하지만 장치가 실제로 연결된 포트를 변경했더라도 새로운 프레임이 관찰되기 전까지는 기존 정보가 남아 있을 수 있다. 반대로 정상적으로 연결되어 있지만 일정 시간 동안 통신하지 않은 장치의 항목도 제거될 수 있다.

이를 개선하려면 장치가 다른 포트에서 프레임을 보내는 순간 해당 MAC 주소와 포트의 연결 정보를 갱신할 수 있다. 또한 네트워크의 연결 상태 변화나 포트 상태를 감지해 관련 항목을 갱신하거나 제거하는 방법을 사용할 수 있다. 다만 이러한 방법을 사용하더라도 타임아웃은 오랫동안 사용되지 않은 학습 정보를 정리하는 데 유용하다.

             Task 2 — ARP 분석

Wireshark를 이용하여 ARP 패킷을 캡처하고 ARP Request와 ARP Reply를 분석하였다.

ARP Request의 출발지 IP 주소는 `192.168.0.35`, 출발지 MAC 주소는 `38:d5:7a:c1:a2:55`였다. 대상 IP 주소는 `192.168.0.1`이었으며, 대상 MAC 주소는 `00:00:00:00:00:00`으로 표시되었다. Ethernet 목적지 MAC 주소는 `ff:ff:ff:ff:ff:ff`로, 브로드캐스트 방식으로 요청이 전송되었음을 확인하였다. 이는 요청 장치가 대상 IP 주소에 대응하는 MAC 주소를 아직 알지 못하기 때문이다.

ARP Reply에서는 출발지 IP 주소가 `192.168.0.1`, 출발지 MAC 주소가 `88:36:6c:e7:23:d0`로 확인되었다. 목적지 IP 주소는 `192.168.0.35`, 목적지 MAC 주소는 `38:d5:7a:c1:a2:55`였다. 응답은 요청을 보낸 장치의 MAC 주소를 목적지로 하여 전달되었다.

이 결과를 통해 ARP Request는 같은 LAN에서 IP 주소에 대응하는 MAC 주소를 알아내기 위해 브로드캐스트로 전송되고, ARP Reply는 해당 IP 주소와 MAC 주소의 대응 관계를 알려 준다는 것을 확인하였다.

         ARP 테이블 비교

ARP 캐시 삭제 전후의 테이블을 비교한 결과, 삭제 전에는 7개, 삭제 후에는 4개의 항목이 확인되었다. 항목 수가 3개 감소했으며, 두 테이블 모두 게이트웨이 IP 주소 `192.168.0.1`과 MAC 주소 `88-36-6c-e7-23-d0`를 포함하고 있었다.

이는 ARP 캐시 삭제 후 게이트웨이와 통신하는 과정에서 해당 게이트웨이의 MAC 주소가 다시 확인되어 동적 항목으로 등록되었기 때문으로 볼 수 있다. 반면, 멀티캐스트 주소와 브로드캐스트 주소 등의 정적 항목은 캐시 삭제 전후에 차이가 있었다.

ARP 테이블은 IP 주소와 MAC 주소의 대응 관계를 저장하며, 같은 로컬 네트워크에서 다음 홉으로 데이터를 전달할 때 활용된다는 것을 확인하였다.

            Task 3 — Switching and Flooding

48개의 포트와 400개의 단말이 있는 환경에서 총 48,954개의 프레임을 처리하여 기본 스위치와 직접 구현한 스위치의 성능을 비교하였다. 스위치의 MAC 주소 테이블 용량은 64개로 설정하였다.

기본 스위치의 불필요한 프레임 전달 횟수는 323,380회였고, 직접 구현한 스위치는 188,048회였다. 따라서 불필요한 전달 횟수가 약 42% 감소하였다. 두 방식 모두 정상적으로 전달된 프레임은 46,347개였으며, 추가로 전달에 실패한 프레임은 발생하지 않았다.

직접 구현한 스위치는 프레임의 출발지 MAC 주소와 수신 포트를 학습 테이블에 저장하고, 목적지 MAC 주소를 알고 있으면 해당 포트로만 프레임을 전달하도록 구현하였다. 목적지 주소를 알 수 없거나 브로드캐스트 프레임인 경우에는 수신 포트를 제외한 나머지 포트로 프레임을 전달한다. MAC 주소 테이블의 용량이 초과되면 사용 빈도와 마지막 사용 시점을 기준으로 항목을 제거하도록 하였다.

실험 결과, 직접 구현한 스위치는 기본 스위치보다 불필요한 프레임 전달을 줄이면서도 전달 성공 수를 유지하였다. 이를 통해 MAC 주소 학습과 목적지 기반 전달이 네트워크의 불필요한 트래픽을 줄이는 데 도움이 된다는 것을 확인하였다.
